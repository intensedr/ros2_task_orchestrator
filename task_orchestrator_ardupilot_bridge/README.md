# Task Orchestrator ArduPilot Bridge

ROS 2 action and telemetry bridge for ArduPilot. It keeps stabilization and
failsafe behavior in the flight controller while Task Orchestrator owns mission
lifecycle, policy and observability.

## Supported runtime

| Component | Supported | Verified in this workspace |
|---|---|---|
| ROS 2 | Humble, Jazzy | Jazzy |
| Python | 3.10, 3.12 | `3.12.3` |
| pymavlink | `>=2.4.49,<2.5` | `2.4.49` |
| ArduPilot | Copter 4.5-4.8 | `4.8.0-dev` (`6e741784`), SITL |
| MAVLink | MAVLink 2, `ardupilotmega` | Generated by pymavlink |

Install the locked Python dependency when the system package does not provide a
compatible pymavlink:

```bash
python3 -m pip install -r task_orchestrator_ardupilot_bridge/requirements-ardupilot.txt
```

## SITL launch

Start ArduCopter SITL without MAVProxy owning the application connection:

```bash
sim_vehicle.py -v ArduCopter --no-mavproxy
```

Then launch the orchestrator and bridge:

```bash
ros2 launch task_orchestrator_ardupilot_bridge ardupilot_orchestrator.launch.py \
  connection_url:=tcp:127.0.0.1:5760
```

The bridge publishes `/drone/pose`, `/drone/battery` and `/drone/state`. It
updates the orchestrator admission parameters from live heartbeat, battery,
mode, EKF/GPS and failsafe state. The initial launch state is fail-closed.

## Run the SITL mission

After `/drone/state` reports `localization_ok: true`, submit the installed
four-stage route (takeoff, waypoint, hover and land):

```bash
MISSION_FILE="$(ros2 pkg prefix --share task_orchestrator_ardupilot_bridge)/missions/sitl_inspection_route.json"
ros2 run task_orchestrator_examples demo_agent_client run \
  --agent-id ardupilot-sitl-agent \
  --source task_orchestrator_ardupilot_bridge \
  --mission "$MISSION_FILE"
```

For a real flight controller, change `connection_url` to its serial or UDP
MAVLink endpoint and validate the airframe parameters in SITL and HITL first.

## Safety boundary

- Action success requires telemetry confirmation; sending a MAVLink packet is
  not treated as completion.
- Navigation cancellation switches to the configured safe mode (`BRAKE` by
  default). Hover streams the current position setpoint in `GUIDED`, so it does
  not depend on neutral RC throttle input.
- Link-loss behavior still must be configured in ArduPilot itself. The bridge
  cannot command a vehicle after its MAVLink link has already failed.
- Validate every firmware/airframe/parameter set in SITL and HITL before flight.
